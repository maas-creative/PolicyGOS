# ADR 001: 同一オリジンの認証付きWebサービスとして公開する

- 状態: 採用
- 日付: 2026-07-31

## 背景

ローカル版はブラウザ、Node API、OCR、モデルを個別に起動していました。外部公開では、APIキー漏えい、OCRの直接攻撃、任意URL取得による内部ネットワーク接続、無制限な計算資源消費を防ぐ必要があります。

## 決定

- React本番ビルドとNode APIを同じオリジンから配信する。
- 公開APIは利用者別Bearerトークンを必須にし、トークンはブラウザメモリだけに置く。
- OCRはCompose内部へ隔離し、Nodeとの通信にも専用トークンを使う。
- TLSはCaddyで終端する。
- 文書データはサーバーへ永続保存せず、監査メタデータだけをJSONLへ保存する。

## 比較した選択肢

- Cookieセッション: 利用者体験はよいが、アカウントDB、パスワード回復、CSRFトークン、セッションストアが必要になるため今回は採用しない。
- 逆プロキシの共通Basic認証: 簡単だが、利用者別の監査と失効が弱いため採用しない。
- 匿名公開: OCRとモデル費用を第三者が無制限に消費できるため採用しない。

## 帰結

利用者ごとに長いトークンを発行・失効できます。再読み込み時には再認証が必要です。将来、一般利用者向けのアカウント管理が必要になった時点でOIDC又はサーバー側セッションへ移行します。
