# 外部公開構成

## 対象

ここでいう外部公開構成は、インターネットからHTTPSで到達できる一方、PolicyGOSのAPI利用は発行済み資格を持つ利用者に限定され、OCRとモデル資格情報が内部に留まる構成です。匿名で無制限に利用できる公開APIは対象に含めません。

## 構成

1. Caddyが80/443番を受け、証明書の取得・更新とHTTPS終端を担当する。
2. PolicyGOS NodeサービスがReactの本番ビルドと同一オリジンAPIを配信する。
3. Nodeサービスは利用者別Bearerトークンを照合し、レート制限、同時OCR制限、監査記録を実行する。
4. OCRサービスはCompose内部ネットワークだけに公開し、Nodeからの別Bearerトークンを要求する。
5. ReportMeta/OpenUIのモデル資格情報はNodeサービスの環境変数だけに保持する。

ブラウザは利用者トークンをメモリだけに保持します。再読み込み後は再入力が必要ですが、IndexedDBやLocal Storageから長期トークンを奪われる経路を増やしません。Cookie認証を使わないため、今回のAPIにはCookie自動送信を前提とするCSRF対策は不要です。

## 信頼境界

- 公開境界: Caddyより外側。すべて攻撃者入力として扱う。
- アプリ境界: PolicyGOS API。認証後もPDF、JSON、質問文を検証し、容量と頻度を制限する。
- OCR境界: Compose内部のみ。外部公開せず、内部トークンも要求する。
- モデル境界: 選択した外部又は自己運用モデル。文書由来データの送信先として画面に表示する。
- 利用者端末: PDFと確認データをIndexedDBへ保持する。共有端末では作業終了時にワークスペースを消去する。

## 記録と保持

監査JSONLには、時刻、リクエストID、利用者名、HTTPメソッドとAPIパス、状態コード、所要時間だけを記録します。PDF、OCR本文、質問文、モデル応答、トークンは記録しません。Composeの`policygos_audit`ボリュームはサーバー運用者がバックアップとローテーションの対象にします。

URL取得機能を必要に応じて有効化する場合は、`SOURCE_FETCH_ENABLED=true`に加えて`SOURCE_FETCH_ALLOWED_HOSTS`へ接続先ホストを列挙します。許可ホストであっても、DNS解決結果がローカル、プライベート、リンクローカル又は予約済みアドレスなら接続しません。

## 障害時

- Caddyが起動しない: DNSがサーバーを指すこと、80/443番、`POLICYGOS_DOMAIN`を確認する。
- PolicyGOSが起動しない: 公開用利用者トークンとOCRトークンが32文字以上であることを確認する。
- OCRが503: `POLICYGOS_MAX_CONCURRENT_OCR`を超えている。15秒後に再試行する。
- APIが429: 利用者ごとの1分間上限に達している。
- モデル処理が502: ブラウザには一般化したエラーだけを返す。サーバーのリクエストID付きログで詳細を照合する。

## 現段階の限界

認証と監査は複数利用者を識別できますが、文書ワークスペースはサーバー共有されません。複数インスタンスへ水平分散する場合は、レート制限状態と認証セッションを共有ストアへ移す必要があります。組織間のデータ分離を要する場合は、テナントIDを全保存データと認可判定へ組み込む別設計が必要です。
