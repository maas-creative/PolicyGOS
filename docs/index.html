PUBLIC RELEASE / 0.1.0

政策評価PDFのデータ抽出・確認・画面生成

PolicyGOSは、政策評価PDFを構造化し、抽出値と出典ページを人が確認した後、 確認済みデータだけから説明画面を生成します。

01 / PROCESS

データ確認後に画面を生成

文書の読取り、構造化、人による判断、表示生成を別の処理として接続します。

  1. 01

    OCR ADAPTER

    ページ単位で読む

    デジタルPDFを処理し、必要な場合はOCRへ切り替えて、ページ・本文・表を共通形式へ変換します。

  2. 02

    REPORTMETA

    値と根拠を結ぶ

    政策、事業、指標、値、引用、ページ番号をPolicyDataset v1へ整理し、引用箇所を検査します。

  3. 03

    HUMAN REVIEW

    人が確定する

    抽出値とPDF原本を並べ、確定・修正・却下を記録します。未確認値は次の処理へ渡しません。

  4. 04

    OPENUI

    説明を構成する

    確認済みIDを登録済みの表示部品へ結び付け、質問と読み手に応じた説明画面を構成します。

02 / VALIDATION RULES

表示の前に満たす、3つの規則。

生成結果の見栄えではなく、入力から表示までの参照関係を検査します。

  1. R-01

    引用は指定ページに存在する

    ReportMetaの引用文をOCRページ本文と照合し、一致しない抽出結果を受理しません。

  2. R-02

    数値には根拠と確認状態がある

    根拠を持ち、人が確認または修正した値だけをOpenUIへ渡します。

  3. R-03

    生成結果は許可部品だけで構成する

    登録済みの10種類の部品と許可した操作を使い、生成されたHTMLやJavaScriptは実行しません。

03 / DEPLOYMENT

端末内でも、認証付きサーバーでも。

同じ実装を、ローカル確認環境とHTTPSで到達できる外部サーバー環境に配置できます。

MODE A

ローカル実行

  • ブラウザとローカルAPIで実行
  • PDFと確認データはIndexedDBへ保存
  • ローカル限定モードを選択可能

MODE B

外部サーバー実行

  • CaddyによるTLS終端
  • 利用者別Bearerトークンと監査記録
  • OCRサービスを内部ネットワークに限定

CURRENT BOUNDARY

外部サーバー版は複数の利用者資格を識別しますが、文書ワークスペースは各ブラウザに保存されます。 組織別テナント、サーバー上の文書共有、水平分散は現在の対象外です。
