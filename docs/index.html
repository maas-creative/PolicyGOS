From document to explanation

生成する前に、根拠を確かめる。

PDFをそのまま言語モデルへ渡して回答を得るのではなく、抽出、検証、人による確認、 表示生成を分けています。

  1. 01

    文書を読む

    デジタルPDFはPyMuPDFで処理し、必要な場合はOCRへ切り替えます。

  2. 02

    構造化する

    政策、事業、指標、値、引用、ページ番号をPolicyDatasetへ整理します。

  3. 03

    人が確認する

    抽出値とPDF原本を並べて確認し、確定、修正、却下の履歴を残します。

  4. 04

    説明を組み立てる

    確認済みIDだけを、許可されたOpenUI部品へ結び付けて表示します。

Evidence before presentation

見た目より先に、
参照の整合性を守る。

PolicyGOSが扱うのは、生成された文章だけではありません。どの値が、どの文書の、 何ページに書かれていたかをデータ構造として保持します。

A

引用を機械検査

ReportMetaの引用文が指定されたOCRページ内に存在しない場合、抽出全体を失敗として扱います。

B

未確認値を公開しない

OpenUIへ渡せる数値は、根拠を持ち、人が確認または修正した値に限定されます。

C

任意コードを実行しない

生成結果は10種類の登録部品と許可された操作だけで構成し、HTMLやJavaScriptを受け付けません。

Architecture

役割を分け、失敗を見える状態に。

01 · INPUT

OCR Adapter

既存OCRサービスの応答を、ページ・ブロック・表を持つ共通形式へ変換します。

02 · STRUCTURE

ReportMeta

構造化出力をスキーマ検証し、文書ID、引用、値と根拠の関係を確認します。

03 · REVIEW

PolicyDataset

確認状態と操作履歴を保持し、元PDFとともにブラウザ内へ保存します。

04 · PRESENT

OpenUI Library

質問と読み手に応じ、検証済みIDを使って説明画面を構成します。

Current scope

単一端末での政策文書確認に対応

現在の実装はローカルでの確認作業を対象とします。複数利用者で運用する場合は、 認証、テナント分離、サーバー側の監査ログ、バックアップを追加する設計です。
